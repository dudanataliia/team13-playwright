# TC-08 — Preview news content

**Description:** Verify that the user can preview news content after entering valid data and that the preview matches the input.

**Preconditions**

- The user is logged into the system.
- The "Create News" form is open.

**Steps**

- Navigate to GreenCity News and click "Create News".
- Enter a valid title in the "Title" field (e.g., "Test Preview").
- Enter valid content in the "Main Text" field (e.g., "This is a test preview content").
- Click the "Preview" button/link.
- Verify that the preview mode displays the entered "Title" and "Main Text".

**Expected Result**

- The preview mode opens.
- The entered title (e.g., "Test Preview") is displayed correctly.
- The entered main text (e.g., "This is a test preview content") is displayed correctly.
- The preview displays the current date.
- The author's name is displayed correctly.
- A "Back to editing" button/link is available for returning to the edit mode.

---

## Automation notes

- "Preview" opens a dedicated route `#/greenCity/news/preview` (not a modal) and is enabled with
  just a Title and Main Text (no tag required).
- The preview reuses the news-detail layout: `.news-title`, `.news-text-content`,
  `.news-info-date`, `.news-info-author`, `.tags-item`; "Back to editing" is `a.button-link`.

### Functional behaviour confirmed (passes)

- Preview opens and shows the entered **Title** ("Test Preview"), **Main Text**
  ("This is a test preview content"), the **current date** ("Month D, YYYY"), and the **author**
  ("by &lt;name&gt;"). The "Back to editing" link is present.

### Detected product bug (test fails by design)

**"Back to editing" does not return to the editable form.** Clicking it navigates to
`#/greenCity/news/create-news`, but the form is **not rendered at all** — there are no Title
(`textarea[formcontrolname="title"]`) or Main Text (`.ql-editor`) fields on the page. This breaks
the expected result "A 'Back to editing' button/link is available for returning to the edit mode".
