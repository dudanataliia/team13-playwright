# TC-03 — Tag selection (1 to 3 tags)

**Description:** Verify that the user can select between 1 and 3 tags from the predefined list.

**Preconditions:**

- The user is logged into the system.
- The "Create News" form is open.

**Steps:**

1. Navigate to [GreenCity News](https://www.greencity.cx.ua/#/greenCity/news) and click "Create News".
2. In the "Tag" field, select one tag ("News").
3. Fill in the required fields:

- Title: "Test"
- Main Text: "Test content with 20 chars"

4. Click "Publish".
5. Verify that the news is published with the "News" tag.
6. Open the "Create News" form again.
7. Select three tags: "News", "Events", "Education".
8. Click "Publish".
9. Verify that the news is published with all three selected tags.
10. Attempt to select a fourth tag ("Initiatives").
11. Verify that selecting a fourth tag is blocked.

**Expected Result:**

- The user must select at least one and at most three tags.
- Selecting more than three tags is not possible.

**Automated Verification:**

- Check the number of selected tags.
- Verify that a fourth tag cannot be selected.
- Confirm that the published news contains the correct tags.

---

## Automation notes

- Each run uses unique titles (`TC03 ... ${Date.now()}`) so reruns never collide.
- Published tags are rendered in UPPERCASE via CSS (`text-transform`); comparison is
  case-insensitive and the `|` separators are filtered out.
- After `Publish`, the app redirects to `#/ubs`; the published item is verified by
  reopening the News list and reading the card by its unique title.

### Detected product bug — tag state is not reset when reopening the form

Reproduced both via direct navigation and via the in-app "Create News" button:

1. Publish a news with 1 or 3 tags.
2. Open "Create News" again → **the previously selected tags are still highlighted**
   (the form does not start clean).
3. Because of this stale state, clicking one more tag results in **4 selected tags**,
   which violates the "maximum 3 tags" rule.

The test asserts that a reopened form has `0` selected tags and that the count can never
exceed `3`. These assertions currently **fail by design**, flagging the bug.
